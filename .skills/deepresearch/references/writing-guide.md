# 写作指南

## 报告格式

```markdown
# [研究标题]

**摘要**
[2–4 句话概括核心发现；直接说结论，不要说"本报告将探讨……"]

---

## 目录
（主章节 ≥ 3 个时必须提供，列出所有一级和二级标题）
- [一、章节标题](#)
  - [子节标题](#)
  ...

---

## 一、[章节标题]

### [子节标题]
[内容，织入引用脚注如 [^1][^2]]

...

## 结论
[直接回答核心研究问题。若用户要求评估、推荐或预测，必须给出明确判断，不能只罗列信息而不表态]

---

## 参考文献
[^1]: 标题 — URL
[^2]: 标题 — URL
...
```

---

## 起草时的写作要求

**内容层面**

- **来源铁律**：所有数据、案例、结论必须来自已爬取的参考资料，禁止凭空生成
- **反幻觉规则**：涉及具体数字（市场规模、排名、时间节点、人物言论）时，必须能在引用来源中找到对应原文。若搜索结果中无法验证某数据点，宁可写"公开数据有限"也不要编造。**尤其禁止虚构未来事件的具体数据**（如未上映电影的票房、未发布产品的销量）——这是最严重的质量事故
- **跨来源综合**：优秀的见解来自**多个来源的交叉验证和模式识别**，而不是逐条摘录。写作时问自己："我是否在用自己的分析语言综合多个来源的共同信号？"而不是"来源A说X，来源B说Y"地并列。每个主章节至少综合 3 个不同来源。
- **定量问题必须给数字**：用户问题中含"比重是多少"、"年用量是多少"、"数量、比例"等明确数量要求的，报告必须给出具体数值或合理估计区间（含推算依据）。"数据有限，难以精确"不是答案——即便是估算，也要写出"基于X推算，约为Y，误差±Z%"。**摘要中给出的数字必须与正文推算过程一致**；若摘要给出估算区间，正文的推算步骤必须能推出同一区间——两者矛盾是硬错误，会直接拉低洞察和可读性评分
- **维度语义忠实**：用户命名的每个维度，按字面语义理解，不得偷换。"融资情况"指实际融资活动（债券发行、配股、信贷额度），≠ "资本充足率/偿付能力"；"增长幅度"指实际业绩增速，≠ "市场地位"；"信誉度"含信用评级 + 历史赔付/违约记录。遇到模糊维度，在章节首句说明理解方式（"本节将'融资情况'理解为近五年的资本补充操作……"），不得悄悄替换
- **预测要有数量级与时间节点**：趋势预测不能只用"将增长"、"会扩大"等定性词汇，需给出具体时间节点（"到2027年"）和数量级（"预计年均增长X%"、"市场规模约达Y亿元"）；无法预测时，说明制约预测的核心不确定因素
- **数据时效性**：引用超过 2 年的核心市场/行业数据需标注获取年份；超过 3 年的数据需说明是否存在更新来源，或注明"截至[年份]最新数据"
- **批判性分析**：对报告中的主要论点或建议，不能只说"有效"或"推荐"，还要说明：在什么条件下适用、有哪些已知局限、业界是否有不同声音。把"为什么"写清楚，比堆砌"是什么"更有价值
  - 弱："XYZ 策略已被证明有效。"
  - 强："XYZ 策略效果量 d=0.8，但主要证据来自北美环境；国内实施时忠诚度下降约 40%，核心原因是教师培训资源不足——落地时需优先解决培训问题。"
- **覆盖广度原则**：报告不能只深挖用户显式提到的内容，还必须覆盖该领域"默认期待存在"的标准子类别（来自阶段 1c 清单）。具体要求：
  - **策略/干预类报告**：不只列出每种策略"是什么"，还必须覆盖"如何实施"层——包括个性化选择依据、关键前提条件、实施支持机制（如培训、协作、评估）。缺少实施层的策略报告只完成了一半任务。
  - **市场/行业/政策类报告**：正文核心分析章节之前，必须有宏观背景铺垫，说明：该领域当前所处的宏观环境（政策走向、经济驱动力、监管框架）。这不是可选的背景，而是让读者理解后续分析结论的必要基础。
  - **比较分析类报告**：每个被比较的实体必须覆盖所有用户指定的比较维度。某实体在某维度信息不足时，写"[维度X]：公开信息有限，已知情况为……"，而非直接跳过该维度。维度覆盖不对称是常见的低分原因。
  - **学术/理论类报告**：用户要求分析的每个理论框架（如"后殖民主义视角"、"东方学批判"）必须有独立的实质性讨论，包含：该框架的核心主张、代表性论者/著作、对当前课题的具体适用方式。不得将多个框架合并为"多元视角"一节泛泛带过。
- **洞察密度**：报告质量不取决于字数，而取决于洞察密度。每个主章节应有至少 1 条**跨来源推断性结论**——不是"来源A说X，来源B说Y"的并列，而是"根据A+B可以推断C"。洞察的具体形式：
  - **对比洞察**：两组数据/观点的差异背后揭示的深层原因（"X机构与Y机构数据差 50%，原因在于统计口径不同——这意味着行业实际规模被系统性低估"）
  - **推演洞察**：从已知事实推断出的隐性结论（"X 技术成本已降至临界点，意味着商业化窗口正在开启，先发布局者将获得网络效应优势"）
  - **结构化重组**：用新框架整合碎片信息，让读者看到原来看不到的关系（如将 N 个方案归纳为"三层梯队"或"四大阵营"，并为框架命名——评分者对有名字的框架评分更高）
  - **因果链**：把多个相互影响的因素串成箭头链条，例如："加息 → 投资收益提升 → 资本生成加速 → 偿付能力上升 → 评级上调 → 融资成本下降"。因果链比孤立列举因素更能体现分析深度
- **机制分析（技术/科学课题的核心要求）**：对每个关键结论，不只说"是什么"，要说清"为什么"——即驱动该现象的物理/化学/工程/经济机制。比较方案时，要解释选择某方案的本质原因（不只是列特性），以及它的局限来自哪个底层约束。
  - 弱："ALD 因其共形性而被选用。"
  - 强："ALD 的共形性源于其自限制的表面化学反应——每个 ALD 半循环只在暴露的悬挂键上发生单层反应，深宽比大于 10:1 的孔洞内部也能均匀覆盖；PVD 受方向性沉积限制，在同等深宽比下底部覆盖率显著降低。"
- **结论有态度**：遇到"哪家公司最值得关注"、"哪个方向最有前景"、"这个思路是否可行"这类问题，结论部分必须给出明确判断，不能用"各有优劣，需具体情况具体分析"敷衍

**多实体比较的一致性模板**

当需要比较 N 个公司、研究组、国家、方案等实体时：

- **统一子标题结构**：每个实体的介绍段落使用完全相同的子标题顺序。若用户要求比较"融资、技术路径、产品进度、团队"，则每家公司都严格按这四个子标题展开，不得一家详写融资、另一家详写技术。
- **用户指定的比较维度 = 子标题**：如果用户在提问中列出了要比较的维度，这些维度直接用作每个实体的子标题（或汇总表格的列名），保持原措辞。
- **汇总表格**：N ≥ 3 个实体时，优先在章节末尾加一张汇总对比表（行为实体，列为比较维度），让横向比较一目了然。

**表达层面**

- **受众适配**：始终对齐阶段 1 判断的受众类型
  - 所有缩写首次出现必须写全称 + 括号内中文说明，无论受众类型（正确：TEACCH（结构化教学系统）；错误：直接写 TEACCH）
  - 面向普通读者（教育、职业、生活类课题）：每个抽象概念配具体例子，每个建议说明如何落地，避免连续堆叠专业术语
  - 面向专业读者：精准术语为主，数据和具体方案比理论描述更重要
  - **受众不确定时默认为"普通读者"模式**：宁可对专家稍显啰嗦，也不要让普通读者看不懂
- **入门引导节（所有报告强制）**：正文第一个核心章节之前，必须有一个简短的"背景与基本概念"节（≥300字），为读者建立理解后续分析的基础框架。不能直接跳入深度分析——即使目标读者是专业人士，快速建立共识仍然有价值
- **多项对比用表格**：凡涉及多个方案、公司、国家、方法的横向比较，优先用对比表格而非分段描述；重要的列可加"综合评价"或"适用场景"行，避免表格只有事实没有判断
- **全景总览表（调研型/筛选型报告强制）**：当报告涉及多个方法/策略/技术/方案的梳理时，在详细分析前先用一张汇总表列出**所有主要选项**（每个一句话描述），然后对重点选项深入展开。这同时满足"广度"和"深度"的评估要求
- **Mermaid 图表**：流程、依赖关系、时间线优先用 Mermaid 呈现
- **合成型报告：趋势提炼优先于清单枚举**：当课题要求"总结/梳理/分析趋势"时，核心价值在于提炼模式，不在于完整列举。每个趋势选 2–3 个最典型案例支撑结论，其余同类案例一句话带过即可。按时间线或按对象逐一罗列是枚举，不是趋势综合。
- **筛选型报告：篇幅与重要性对应**：当用户问"哪些 X 被使用/有哪些因素"时，入选项占主篇幅，排除项用一段话统一说明排除原因（不单独成章）。
- **人群画像报告：数据 + 叙事**：画像类课题除统计数据外，每个细分人群需要有叙事段落："这类人群的核心诉求是…；对决策者的关键启示是…"，把数据翻译成可操作的洞察。
- **技术类报告：缩写集中导引**：当报告密集使用专业缩写（≥5 个不同缩写），在目录之后、正文开始之前加一张 2 列表格（"缩写 | 全称 + 一句话解释"）。正文第一次出现时仍需展开，之后可直接使用缩写。
- **不重复**：后续章节不复述前章已有内容；同一 URL 只出现一次
- **段落长度控制**：单段 ≤200 字；一段只讲一个话题；话题转换时加新标题；列表项超过 5 条时改用表格
- **摘要写法**：首句直接给出最重要结论（含具体数字），不用"本报告将探讨…"开头；2–4 句覆盖：核心结论 + 最意外发现 + 对决策者的关键启示。**若核心数据为推算估计，在摘要中直接给出区间并注明置信度**（如"约30%（置信区间：20-40%）"），而非回避不写

**引用格式**

- 正文中用 `[^1]`、`[^2]` 标注，文末统一列出
- 只记录实际读取过全文的来源；来源冲突时优先采信原始内容

**篇幅参考**：6000 字以上，多维度、多比较对象的课题不设上限

## 起草后：修订检查

起草完成后，做一轮快速扫描，重点检查以下容易遗漏的问题：

> ⚠️ **重点优先保证（对综合评分影响最大）**：洞察密度（跨来源推断）、批判性视角（局限分析）、定量数据、结论表态、指令遵循（用户问号直接回答）

| 检查项 | 常见问题 |
|--------|---------|
| 报告类型与格式是否对应？ | 合成型课题是否在"提炼趋势"而不在"枚举清单"；筛选型课题是否把篇幅重心放在入选项上；人群画像是否有叙事层而不只有数据表 |
| 用户每个问号对应的问题有没有直接回答？ | 扫描用户原始提问中的每个"？"——报告中是否有段落（通常在对应章节的结尾或结论中）直接、明确地回答了它？ |
| 定量问题有没有给出数字？ | 用户问"比重是多少"、"年用量是多少"、"数量比例"——检查报告是否给出了具体数值或估计区间，而非只有"受数据限制，难以精确"等回避表述 |
| 并列子问题深度是否均衡？ | 用户并列提出了 N 个问题（如"现状/因素/政策"、"趋势/替代可能性"）——每个问题的覆盖篇幅是否大致均衡？最多/最少覆盖比是否 ≤ 2:1？明显偏薄的问题需要补充内容 |
| 领域标准类别覆盖率是否 ≥80%？ | 对照阶段 1c 的领域标准类别清单——是否有主要子类别被完全跳过？完全跳过即使只有一个也会被评为"覆盖不全" |
| 市场/政策类是否有宏观背景节？ | 是否在核心分析前建立了宏观环境框架（政策/监管/经济驱动力）？仅用引言一两句带过不算 |
| 策略类是否有实施支持层？ | 除了"用什么策略"，是否覆盖了"如何实施"（个性化选择、关键条件、实施障碍、资源/培训/协作机制）？ |
| 学术框架类是否逐维度独立展开？ | 用户要求的每个理论视角是否有独立子节？有没有将多个框架合并为泛化的"多元视角分析"而跳过各框架的具体应用？ |
| 比较分析每个实体维度是否完整？ | 对比表格中是否有空白格（某实体缺某维度）？空白格应填"信息有限：……"而非留空 |
| 预测是否有数量级和时间节点？ | 趋势预测是否包含具体年份和数量级，而非只有"将增长"、"预计扩大"等定性词汇 |
| 数据时效性是否注明？ | 超过2年的核心数据是否标注了获取时间 |
| 子问题清单全部覆盖？ | 用户明确提出的每个维度/子问题都有对应章节 |
| 用户指定维度直接成了章节标题？ | 不能合并或替换用户命名的维度，不能新增用户未要求的同级维度 |
| 多实体比较是否以实体为主轴？ | 当用户要求"N个公司/方案各自提供X/Y/Z信息"时，是否每个实体独立成节而非按维度轴组织 |
| 研究主体/范围有没有越界？ | 若用户限定了地域、学科、时间范围，检查是否有章节超出该范围 |
| 用户提及的框架原理有没有介绍？ | 提到"GCS算法"、"PRM"等具体技术，需有基础原理说明 |
| 结论有没有明确表态？ | 用户问"哪个最好/是否可行"，结论不能只罗列，必须判断 |
| 批判性视角有没有缺席？ | 有没有章节只讲优点不讲局限，或只给结论不解释原因 |
| 机制/原因有没有解释清楚？ | 每个关键结论后面是否回答了"为什么"——而不只是描述"是什么" |
| 洞察密度是否足够？ | 每个主章节是否有 ≥1 条跨来源推断性结论？（不是"A说X，B说Y"并列，而是"根据A+B推断C"）对比发现、推演结论、因果链、结构化框架均算 |
| 摘要数字与正文计算是否一致？ | 若摘要给出估算数字（如"50-70万条/年"），正文的推算步骤必须能得出同一区间；若两者矛盾，一定要修正，这是insight评分的硬扣分项 |
| 用户指定维度是否按字面理解？ | "融资情况"≠"资本充足率"；"增长幅度"≠"市场地位"；"比重"必须给数字。若维度含义有歧义，在章节开头注明理解方式，不得悄悄替换 |
| 篇幅扩充是否伴随洞察扩充？ | 内容如有增加，是否同时增加了新的洞察点？篇幅增加但洞察不增，会导致洞察密度下降、读者体验变差 |
| 多实体比较结构是否统一？ | 比较 N 个实体时，每个实体的子标题顺序是否完全一致，是否有汇总表格 |
| 目录是否齐全？ | 主章节 ≥ 3 时是否在摘要后附了目录 |
| 摘要是否符合规范？ | 首句是否直接给出最重要结论（含具体数字）？是否避免了"本报告将探讨…"开头？是否2–4句覆盖：核心结论+最意外发现+关键启示？ |
| 篇幅是否达标？ | 正文（不含参考文献）是否 ≥6000 字？多维度/多比较对象课题篇幅是否与复杂度匹配？ |
| 受众适配：缩写有没有充分解释？ | 面向普通读者时，不只是写全称，还要有一句话解释含义 |
| 受众适配：有没有可操作的实例？ | 面向实践者时，每个建议是否有具体的"怎么做"步骤 |
| 入门引导节是否存在且充分？ | 正文第一个核心分析章节之前，是否有≥300字的背景/概念铺垫？是否直接跳入深度分析而未建立共识？ |
| 全景总览表是否存在？ | 涉及多方法/策略/技术梳理时，是否在详细分析前有一张汇总表列出所有主要选项？仅有深入分析而无全景总览会被评为"覆盖不全" |
| 有没有虚构/无来源的具体数据？ | 检查所有具体数字（市场规模、排名、百分比）是否都能在引用来源中找到对应原文。尤其警惕：未来事件的具体数据（未上映电影票房、未发布产品销量）绝对禁止虚构 |
| 段落长度是否超标？ | 是否有单段>200字的情况？信息密度过高的段落拆分为多段或转为列表/表格 |
| 对比内容有没有用表格？ | 多项并列内容如用文字段落描述，改为表格 |
| 来源够不够多样？ | 参考文献是否过于集中于一两个来源；每个主章节至少引用了3个不同来源 |
