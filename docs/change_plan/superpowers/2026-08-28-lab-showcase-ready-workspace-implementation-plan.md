# Laboratory Showcase Ready Workspace Implementation Plan

English | [中文](2026-08-28-lab-showcase-ready-workspace-implementation-plan.zh.md)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build one DeepSeek Harness application in which Projects, Knowledge, Devices, Conversation, Experiments, Runs, Evidence and reports share Host-backed records and a complete keyless laboratory flow.

**Architecture:** Add a general root application-view registry and an additive sidebar navigation region to the existing Harness shell. Keep the shipped Conversation mounted as the only chat implementation, render laboratory context and lifecycle records through its public slots, and move Project, Experiment, Run and Artifact ownership to Host services.

**Tech Stack:** TypeScript 6, React 18, Cordis plugins, `dsh.client` slot runtime, Typert/JSON Web Facade, Session event logs, storage-domain persistence, SQLite Runtime Provider, Vitest, keyless snapshots and browser acceptance tests.

**Spec:** [OpenSpec design](../../../openspec/changes/lab-showcase-ready-workspace/design.md), [requirements](../../../openspec/changes/lab-showcase-ready-workspace/specs/) and [tracked tasks](../../../openspec/changes/lab-showcase-ready-workspace/tasks.md).

## Global Constraints

- Use Node 24 for every local command.
- Keep `examples/lab-web` as the only product prototype entry and keep the default Web profile unchanged.
- Preserve the existing `conversation`, `sidebar`, `workspace`, `details`, theme, trajectory and attachment owners; add only documented child slots and service methods.
- Do not use `sidebar.footer.action`, `window` custom events, URL hashes, a second composer or a second application shell for laboratory navigation.
- Project, Experiment, Run and Artifact IDs are generated by their owning Host services and remain branded across package boundaries.
- Anything model-visible is reconstructable from Session events; update TypeScript and Python SDK projections for new Session event members.
- UI strings live in locale dictionaries. The keyless UI labels deterministic and mock Providers without presenting them as production capabilities.
- Keep raw JSON behind an explicit diagnostic affordance; tables, cards and detail panels are the primary representation.
- Each non-trivial implementation batch updates the proposed Agent Note, affected README/JSDoc and a real runnable keyless snapshot when user- or model-visible behavior changes.
- Use focused behavior tests for service and protocol work. Do not add test-driven ceremony for isolated CSS or copy edits, but every new shared interface starts with a failing contract test.

## Execution checkpoints

Luna must stop for review after Tasks 1, 4, 8 and 11. Task 1 changes shared Harness UI contracts; Task 4 changes durable Runtime records; Task 8 changes model-visible Session output; Task 11 is the product acceptance point. A checkpoint report contains the exact commands run, passing output summary, changed public interfaces, remaining OpenSpec tasks and any deviation from this plan.

The implementation is complete only when the browser journey starts with no Session, uses one existing Harness composer, reloads Host-backed records successfully and finishes a keyless experiment with a navigable report. Unit tests or individually renderable pages do not satisfy this condition.
