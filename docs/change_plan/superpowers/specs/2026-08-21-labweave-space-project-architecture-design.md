# LabWeave 空间、项目与实验流程架构设计

## 1. 设计目标

本次调整解决当前 Demo 的三个根本问题：

1. 首页、项目管理、全局配置和单项目功能混在同一层侧栏，用户无法判断当前上下文。
2. 多个实验项目共用鼠脑空间转录组的 Workflow、执行事件和记录，导致项目内容串用。
3. 从其他项目进入后，鼠脑空间转录实验组无法稳定重新进入，项目阶段和页面状态没有按项目保存。

设计保持单文件 HTML 前端演示形态，不接入真实后端、设备或实验数据。产品重点仍是展示 Agent 能完成的实验理解、信息补齐、规划、优化、执行辅助、结果判断、异常重规划和归档能力。

本文覆盖并替代以下旧设计中的导航与项目数据组织规则：

- `2026-08-21-global-capability-modules-design.md` 中“全局模块与项目菜单同时作为顶层侧栏入口”的规则。
- `2026-08-21-ai-native-workspace-design.md` 中未区分工作台、配置中心和项目内层空间的导航规则。

旧文档中的知识库、Agent、Workflow、设备、人员模块内容，以及规划门禁、执行结果、异常重规划等业务要求继续保留。

## 2. 总体信息架构

应用划分为三个互斥的页面上下文，但不向用户提供抽象的“空间切换器”。每次只展示一套与当前任务相关的侧栏菜单。

### 2.1 工作台

工作台是默认入口，侧栏只包含：

- AI 首页
- 项目管理
- 跨项目执行监控
- 侧栏底部固定入口：配置中心

AI 首页通过对话描述实验目标并创建项目；项目管理用于搜索、筛选、进入已有项目；跨项目执行监控集中展示所有正在执行项目的状态和异常，不属于任何单个项目。

工作台不展示知识库、Agent、Workflow、设备和人员的展开菜单，也不展示某个当前项目的阶段菜单。

### 2.2 配置中心

配置中心通过工作台或项目侧栏底部的齿轮按钮进入，是独立页面上下文。侧栏只包含：

- 配置总览
- 知识库
- Agent
- Workflow
- 设备管理
- 人员与权限

配置中心顶部提供“返回工作台”或“返回原项目”动作，不使用工作空间下拉切换器。

直接点击齿轮进入时，返回工作台进入前的页面；从项目的知识、Workflow、设备或人员缺口进入时，记录来源项目、来源页面和缺口类型，配置发布后返回原项目原阶段并刷新引用状态。

配置中心维护全局可复用资产。知识库、Agent、Workflow、设备和人员模块的具体内容继续采用此前已确认的设计，不在配置页面内部重复添加这些模块的二级总菜单。

### 2.3 项目空间

项目空间只能通过 AI 首页新建项目、项目管理列表、最近项目或跨项目监控中的项目详情进入。进入后，整套侧栏替换为当前项目专属菜单：

- 项目总览
- 实验规划
- 计划确认
- 执行监控
- 步骤编排
- 结果与判断
- 实验归档
- 侧栏底部：返回项目管理
- 侧栏底部：配置中心

项目空间不展示其他项目详情，也不直接维护全局配置资产。发现能力缺口时，当前页面提供带上下文的“去配置中心补齐”入口。

## 3. 导航与返回规则

### 3.1 进入项目

所有项目入口统一调用 `selectProject(projectId, targetPage)`：

1. 保存当前项目的运行态。
2. 按项目 ID 读取项目定义。
3. 按项目 ID 读取该项目运行态。
4. 将上下文切换为项目空间。
5. 渲染目标页面；未指定目标时进入项目总览。

从任何其他项目返回项目管理后，都可以重新进入 `EXP-2026-0417` 鼠脑空间转录实验组。重新进入时恢复该项目自己的阶段、规划进度和执行记录。

### 3.2 退出项目

“返回项目管理”只退出项目页面上下文，不删除、重置或覆盖项目运行态。项目管理列表继续展示该项目的最新阶段、进度、异常和更新时间。

### 3.3 进入配置中心

配置入口保存 `returnContext`：

```text
returnContext = {
  source: workspace | project,
  projectId: 可选,
  page: 来源页面,
  gapType: 可选,
  assetId: 可选
}
```

配置完成或主动返回时，根据 `returnContext` 返回进入前位置。若来源项目不存在，则安全返回项目管理，并给出上下文已失效提示；Demo 中不新增其他兜底分支。

## 4. 可复用项目生命周期

所有实验项目共享相同的产品阶段和页面骨架：

```text
项目总览
  → 实验规划
  → 计划确认
  → 执行监控
  → 结果与判断
  → 实验归档
```

步骤编排是执行阶段的独立工作页，可从执行监控进入并返回。它不是一个新的实验阶段。

统一复用的内容包括：

- Agent 理解实验目标、识别关键缺口和提问的交互方式。
- 流程选择卡、计划完善度、资源冲突和优化建议的表达方式。
- 计划确认、版本锁定、执行监控、结果证据、异常处理和归档页面结构。
- 每个执行步骤的结果字段和状态规则。

不能跨项目复用的运行内容包括：

- 具体 Workflow 和步骤依赖。
- 样本、批次、参数与资源编排。
- 执行事件、当前步骤、步骤结果和附件证据。
- 异常、重规划版本、判断结论和归档记录。

## 5. 项目数据模型

### 5.1 项目定义

`projectDefinitions` 按项目 ID 保存稳定的实验定义：

```text
ProjectDefinition
├── id / name / experimentType
├── objective / samples / owner
├── workflowDefinition
│   ├── workflowId / version / source
│   ├── steps[]
│   └── dependencies[]
├── referencedAssets
│   ├── knowledgeBaseVersion
│   ├── agentProfileVersion
│   ├── deviceCapabilities[]
│   └── personnelQualifications[]
└── demoScenario
```

### 5.2 项目运行态

`projectRuntimeStates` 按项目 ID 保存可变状态：

```text
ProjectRuntimeState
├── currentStage / currentPage
├── planningConversation[]
├── planningCompleteness / unresolvedGaps[]
├── selectedWorkflowVersion
├── planVersions[]
├── resourceSchedule[]
├── executionCursor / executionEvents[]
├── stepResults[]
├── incidents[] / replanningHistory[]
├── judgment
└── archiveRecord
```

项目定义与运行态分离。页面渲染只读取 `currentProjectDefinition + currentProjectRuntimeState`，不再读取一份全局的 `workflowData` 或 `executionEvents`。

### 5.3 全局配置资产

配置中心保存以下独立集合：

- `knowledgeBases`
- `agentProfiles`
- `workflowTemplates`
- `devices`
- `peopleAndRoles`

项目通过 ID 和已发布版本引用这些资产。更新全局资产不会静默改变已确认或执行中的项目；项目需要显式接受新版本，重新确认后才能用于未执行步骤。

### 6.1 鼠脑空间转录实验组

该项目保留此前已经设计的知识验收标准和图像质量检查 Workflow 缺口，用于展示 Agent 引导补齐配置的路径。

### 6.2 空间 ATAC 实验

### 6.3 SeekOne DD 单细胞文库构建

### 6.4 客户自定义实验

该项目使用自定义 Workflow，保留隐性经验缺口示例。缺口补齐后先进入 Workflow 配置页确认和发布，再返回项目完成规划。

## 7. 规划阶段业务逻辑

规划阶段遵循以下顺序：

```text
用户描述实验目标
→ Agent 理解实验
→ 根据 SOP 与知识库识别缺口
→ 在对话中询问或引导补齐全局能力
→ 在对话中展示流程选择并确认
→ 结合当前设备与其他实验状态进行步骤、资源和批次优化
→ 生成计划版本
→ 用户确认后锁定计划
```

流程选择首先在对话框中展示摘要卡，点击详细信息后从右侧抽屉查看步骤、版本、适用条件和缺口。计划优化必须使用当前项目的步骤依赖，以及 Demo 中预设的设备状态和其他正在执行项目状态，不展示与当前实验无关的通用优化文案。

规划页面右侧实验任务空间可收起，并随对话更新计划完善度、已确认信息、待补齐信息、当前 Workflow 和资源计划。

## 8. 执行、结果与重规划边界

### 8.1 执行状态

执行步骤支持：

```text
queued → running → awaiting_result → passed
                                  ↘ failed → replanning → awaiting_confirmation
```

每个步骤必须展示对应结果，包括：

- 状态和完成时间。
- Executor、设备和责任人。
- 产物或输出文件。
- 关键数据指标。
- 图片、附件或人工回报证据。
- Agent 判断与人工确认结论。

### 8.2 不可修改边界

已开始或已完成的步骤不可重新排序、删除、更换 Executor 或覆盖结果。异常步骤的原始结果和证据也不可被新计划覆盖。

步骤编排只允许修改尚未执行的步骤，并校验：

- 前后置依赖。
- 已锁定的时间和资源预约。
- 设备能力和人员资质。
- 批次合并是否影响已执行产物。

### 8.3 异常重规划

执行阶段保留 Agent 对话框。出现异常时，用户可以：

- 让 Agent 根据异常结果生成后续计划新版本。
- 跳转到步骤编排页手动调整未执行步骤。
- 返回计划确认页查看原计划和版本差异。

重规划保留原计划、异常原因和变更差异，只替换未执行部分。新版本确认后才更新执行队列。

## 9. 配置中心模块边界

### 9.1 知识库

入口先展示按知识域划分的知识库项目及当前已录入数据。知识库详情展示文档资料、SOP 步骤、参数规则、决策表、设备能力和历史经验。通过“录入知识”按钮进入 F1–F5 录入流程，而不是进入知识库就直接打开录入表单。

### 9.2 Agent

展示九个 Agent 的职责、阶段、能力、输入输出、工具权限和人工确认边界。配置页不嵌套知识库、Workflow 等其他模块菜单。

### 9.3 Workflow

展示已发布模板、SOP 编译结果、决策表、Executor 绑定和版本。项目缺少 Workflow 时可预生成草稿，跳转到此页确认修改并发布，然后返回来源项目。

### 9.4 设备管理

展示设备统计、搜索筛选、设备台账、通信状态、启用状态、占用项目、能力模型和人工回报兜底。设备占用可以跳转到对应执行项目确认状态。

### 9.5 人员与权限

展示人员、角色、资质、可用性、审批链、任务分配和权限边界，不扩展未确认的组织管理逻辑。

## 10. 页面状态与错误处理

- 项目 ID 不存在：返回项目管理并提示项目不可用。
- 项目运行态缺失：以该项目定义的初始 Demo 状态创建运行态，不借用其他项目状态。
- Workflow 引用缺失：项目停留在规划阶段，显示缺口并提供带来源上下文的配置入口。
- 配置返回上下文失效：返回项目管理，不自动进入其他项目。
- 执行步骤缺少结果：不允许标记步骤通过，也不允许归档。
- 未确认的新计划：不替换当前执行队列。
- 移动端侧栏：工作台、配置中心和项目菜单沿用同一抽屉机制，关闭后可再次打开。

## 11. 视觉与交互原则

- 延续当前深墨绿、暖白、薄荷绿和琥珀状态色的 AI Native 风格。
- AI 首页以对话输入作为主行动，不把技术架构作为主内容。
- 通过页面上下文、标题和返回入口表达层级，不增加“空间 A / 空间 B”之类技术概念。
- 配置中心齿轮固定在侧栏底部；不设置工作空间下拉切换。
- 项目名称和阶段在项目侧栏顶部明确展示。
- 规划与执行采用不同主布局，执行阶段保留对话但以进度、当前步骤、结果和异常为中心。

## 13. 验收标准

### 13.1 层级与导航

- 默认工作台只显示首页、项目管理、跨项目执行监控和配置中心齿轮。
- 配置中心只显示配置模块菜单，并能返回进入前位置。
- 进入项目后只显示当前项目阶段菜单，并能稳定返回项目管理。
- 不存在工作空间下拉切换器。

### 13.2 项目隔离

- 四个示例项目都可重复进入。
- 切换项目后，Workflow、计划、执行记录、结果和归档不串用。
- 空间 ATAC 与 SeekOne DD 项目不出现鼠脑空间转录执行步骤。
- 返回鼠脑项目后恢复离开前的项目阶段和运行态。

### 13.3 规划与配置闭环

- 流程选择在对话中确认，详情从右侧抽屉展开。
- 缺少知识、Workflow、设备或人员时可以进入对应配置模块。
- 配置发布后返回来源项目原阶段并刷新引用状态。
- 信息完整的项目可以不经过缺口补齐，直接生成并确认计划。

### 13.4 执行闭环

- 每个执行步骤都有结果和证据展示。
- 已执行步骤在步骤编排中锁定。
- 异常后可通过 Agent 或人工方式修改未执行步骤。
- 重规划生成新版本和差异，确认后才更新执行队列。
- 结果通过后才允许实验归档。

### 13.5 静态质量

- HTML 和 JavaScript 可解析。
- 页面不存在重复 ID。
- 移动端菜单可打开和收起。
- 输出文件与工作副本内容一致。
- 浏览器关键路径无控制台错误。
